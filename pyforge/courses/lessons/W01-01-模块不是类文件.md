# W01-01 模块不是类文件

## 今晚能感觉到什么

终端里出现 `0.1.0`。这个目录变成能 `import` 的包。没有网站、没有 Django，但你能摸到「这是我的程序」。

## 和 Java 不同的一句

Java：一个 `public class` 对一个文件，文件名必须等于类名。  
Python：**文件就是模块**，目录加上 `__init__.py` 才是包。一个文件里可以放函数、类、常量，没有「一个文件必须是一个类」。

## 示范（先原样跑）

全程用 `uv run`，**不要** `Activate.ps1`（Windows 默认执行策略会红，而且 `uv run` 根本不需要激活）。

**0. 自检 uv**

```powershell
uv --version
```

若提示不是命令：先装，再**重开**终端。

```powershell
irm https://astral.sh/uv/install.ps1 | iex
```

装完把 `%USERPROFILE%\.local\bin` 加进 PATH（安装脚本通常会写，不生效就重开终端）。

**1. 进仓**

```powershell
cd C:\Users\wangqiuxiang\IdeaProjects\pyforge
```

这里已经有 HANDOFF、课文，正常。

**2. 初始化（只做一次）**

没有 `pyproject.toml` 才跑：

```powershell
uv init --lib --name pyforge
```

`--lib` 才会给出 `src/pyforge/` 和能 `import` 的打包配置。不要用光秃 `uv init`（默认不是 src 布局，后面 `import pyforge` 必红）。  
已有 `pyproject.toml` 就跳过本步。

**3. 替换 `__init__.py`（有文件也要换）**

`uv init --lib` 会先写一个带 `def main()` 的 `__init__.py`。看见文件在**不要跳过**。整文件换成：

```python
__version__ = "0.1.0"
```

路径：`src/pyforge/__init__.py`。

**4. 测试**

`tests/test_version.py`（没有就建）：

```python
import pyforge


def test_version_is_semver_shape():
    parts = pyforge.__version__.split(".")
    assert len(parts) == 3
    assert all(p.isdigit() for p in parts)
```

```powershell
uv add --dev pytest
uv run pytest tests/test_version.py -q
uv run python -c "import pyforge; print(pyforge.__version__)"
```

要看到测试绿，以及一行 `0.1.0`。

## 反例（必错，看一眼就懂）

把 `__init__.py` 改成 Java 直觉：

```python
class Pyforge:
    pass
```

`import pyforge` 还能执行，但 `pyforge.__version__` 会 `AttributeError`。  
版本号是**模块属性**，不是某个类的字段。看完改回 `__version__ = "0.1.0"`。

第二个反例：仓库根放一个 `Pyforge.py`（大写 P）再 `import pyforge`。Windows 有时能蒙对，Linux/CI 会炸。包名小写，走 `src/pyforge/`。

## 今晚只改这一刀

- `src/pyforge/__init__.py`（替换，不是「有就不动」）
- `tests/test_version.py`
- 没有 pyproject 时允许 `uv init --lib`

禁止：`Activate.ps1`、Django、`frontend/`、第二个包。

## 验收命令

```powershell
uv run pytest tests/test_version.py -q
uv run python -c "import pyforge; print(pyforge.__version__)"
```

两条都要。
